### Purpose and scope

This document specifies the visual system and the reusable, dynamically adjusting presentation behavior to port after owner approval. It is not a retrospective claim that older patches established design quality. ### Measured workspace composition

The shared layout controller measures the component's usable content width, computed font size, padding and gap. Its initial readable minima are policy tokens: primary scene 32em, details 20em, gap 24px. Two panes appear together only when those minima fit. Otherwise Scene/Details or Network/Workbench toggles select a single pane. Device names and a fixed viewport breakpoint do not determine that choice. CSS container queries provide an initial no-script fallback; the measured controller owns the live mode.

These are shared adjustable design limits, not guesses for each scene or text length. ResizeObserver and font changes invalidate measurement in a batched frame. Unchanged geometry reuses the result. When parallel panes become exclusive, the pane containing the focused control stays visible. Pane and selection state persist across composition changes. Disposal stops scheduling and disconnects observation.

Reservation prevents avoidable jumps when revisiting panels without preserving unlimited empty height from a deeply expanded inspector. The retained minimum is capped to a readable screen, approximately 70% of the current viewport with a 340px floor; naturally active long content can still grow. A hidden zero-width container does not become a new geometry authority.

The lifecycle explanation and playback console follows the primary scene before retained state, buffers and deep bytes. Builder keeps Find, Run ping and camera controls close to the network; Undo, Redo, link failure and authoring actions live in the existing expandable tool group. Builder page navigation is one horizontally scrollable row. Evidence review fixtures sit after the primary scene in an animated Review states disclosure. Connected workspaces use the same measured pane rule.

### Semantic records

Builder uses a shared semantic record renderer instead of projecting every object into the same generic Fact/Value table. Scalar values become key/value groups. Summary, detail and objective content become prose. Arrays and nested records become independently expandable records, using source identity when present. Domain label/value/detail/why records preserve their established hierarchy. Raw source fields remain reachable through a deeper disclosure.

The system derives these forms from record structure, with a small reusable schema vocabulary. It does not invent a unique layout for every field. Labels use sentence case and preserve protocol acronyms; exact source strings, IDs, addresses, checksums, enumerations and CLI output are not rewritten. Generic booleans read Yes/No, since a true reachability fact is not necessarily an enabled feature. Each nested disclosure key includes its full ancestry, so the same child name under different records cannot collide.

The shared disclosure controller animates the arrow and expanding/collapsing content, retains interacted state, and supports reduced motion. Untouched closed sections do not fill the bounded interaction memory and evict sections the user actually opened.

### Materials express meaning

A physical packet, frame, segment, record or provider envelope receives packet optical volume. A local validation, lookup, MTU decision, dependency event or supporting explanation uses quieter supporting glass. Role comes from the actual source event semantics. Physical construction remains a packet object even when construction itself is local; that is an explicit semantic override, not title matching.

Static supporting records may use the shared supporting-glass painter. Moving operation actors and their lenses use the same clipped, geometry-driven glass renderer as packets, including the shared Light/Dark and fallback paths. They retain a neutral palette, the explicit local-operation label and no wire marker. A semantic role must not replace the active object with a flat white panel. The active canvas follows measured morph geometry; no static supporting canvas is installed on a moving actor. Surrounding controls remain quieter than active objects.

### Protocol and layer identity

Protocol identity is data-driven and normalized by the shared presentation layer. The accepted TCP optical palette is the anchor. Network/IP/GRE/MPLS, Ethernet, UDP/QUIC/VXLAN, ICMP, DNS and TLS/application groups have restrained palette signatures. A palette family is not a status: success, warning, selection and failure still use semantic status tokens and explicit labels.

Palette rotation applies to packet canvas color only. It never hue-rotates text or status elements. Expanded, compact and reused packet carriers read the currently active source layer and update their identity together; an Ethernet carrier cannot accidentally keep the previous TCP signature. Protocol labels use the same identity mapping. Each signature operates over the independently authored light/dark optics, rather than applying a dark filter to light mode.

### Results belong to the network

The highlighted forwarding route is derived from the actual trace's node IDs, next-node IDs and link IDs, intersected with the current topology. A stopped boundary uses the actual failureNodeId. It must never substitute the last successful hop or draw an invented continuation.

Every visible piece of an edge, including crossing overpasses, receives the same context/path/stopped emphasis. Geometry is not rebuilt merely to highlight a result. Show forwarding path and Show stopped boundary change the camera only. A stopped result centers its exact boundary at readable zoom. Routed results are hidden when an Ethernet-only topology is selected, rather than attaching unrelated routed evidence to a LAN view.

### Reusability and dynamic adjustment

A shared component is insufficient if every instance still needs manual geometry or length cases. Measurements and source semantics are inputs; shared limits, palette assignments and timing bounds are policies. Reusable controllers derive pane fit, scanner trajectory, byte capacity, camera targets, shape and record composition from those inputs. Explicit exceptions describe domain meaning or accessibility constraints, not arbitrary short/long buckets.

No optical or layout callback commits domain state, advances canonical time or creates a new protocol event. Preserve the existing adaptive reader and docking engine rather than embedding new per-packet motion constants. Changes to shared policy must be audited across all four studies, both appearances and narrow/wide layouts.

## 1. Purpose and authority

HOPSCOTCH should make the internet understandable by letting people follow, open, inspect, and manipulate its mechanisms. The redesign should deliver ambitious motion with the clarity and continuity of an exceptional product teardown animation. A viewer should understand what moved, what was read, what changed, why it changed, and what happened next.

This specification exists to prevent each workspace from inventing its own typography, controls, materials, layouts, and animation habits. It will become the reference for design decisions, visual reviews, and later implementation acceptance. Actual frames and motion studies must accompany its approved rules; adjectives alone cannot establish design quality.

## 3. Experience principles

**Principles implementing R01–R16:** principles 1–8 remain design proposals; principles 9–11 record agreed requirements.

1. **The visualization is the workspace.** Give the network most of the attention and usable area. Introduce information where it supports the task.
2. **Preserve object identity and lineage.** Connect the compact packet, opened anatomy, and departing representation. Supported field changes remain traceable; a response is a distinct packet, and outgoing framing may replace incoming framing.
3. **Give movement a cause and a consequence.** Coordinated motion can be elaborate, but every meaningful movement must connect to a state, action, relationship, or change of scale.
4. **Make depth serve understanding.** Perspective and material reveal containment; inspection presents text close to face-on.
5. **Keep stable anchors.** Playback, navigation, the primary explanation, and access to inspection stay in predictable locations while the scene transforms.
6. **Progressively expose complexity.** Compact travel views, readable field anatomy, and exact-byte inspection are different scales of one information model.
7. **Leave a useful result.** A completed sequence rests on its outcome. A paused frame can be read and inspected without waiting for another animation.
8. **Make provenance visible.** Visual beauty must never make a simulated path look measured, a physical corridor look like verified forwarding, or missing captured data look known.
9. **Design reusable rules, not tuned examples.** A scene declares what is happening, to which objects, and why. Shared behavior derives the movement and composition. A failing example should first challenge that rule, not trigger another local exception.
10. **Adapt deliberately.** Reusability is not constant movement or a universal effect applied everywhere. Respond to meaningful content, geometry, state, and viewport changes while keeping the user's reference points dependable.
11. **Carry continuity into the details.** A highlight belongs to the same causal sequence as the packet it emphasizes. Its appearance, hold and release must feel intentional; nested components inherit the common motion rules rather than switching abruptly between visual states.

The first audience assumption is a curious learner who wants to understand a mechanism, with a second depth of interaction for someone inspecting exact protocol behavior. This is a proposed information hierarchy, not permission to remove technical tools.

## 9. Motion, camera, and playback

### Choreography rules

Each sequence describes its trigger, source object, movement, destination, reading moment, and resting state. Related movements may occur together: a field can lift while the relevant table expands and the chosen output comes into focus. The composition must make their relationship apparent.

Describe those elements as semantic goals and shared behavior inputs. A storyboard establishes causal order and teaching emphasis; it should not require hand-authored coordinates, dwell points, or durations for every field value. The existing composition is not a constraint on the ground-up visual redesign.

Use broad spatial transformations, changes of scale, unfolding, containment, and continuous reassembly. Merely moving text between boxes or fading cards does not meet the ambition. One causal focus can include several coordinated moving parts; it does not mean one moving object at a time. Avoid unrelated background loops competing with the explanation. Reflections may express material and lighting without representing a network event, but must not look like new traffic or a state change.

### Continuity at every component scale

**Agreed:** the continuity rule applies to temporary highlights and all other subcomponents, as well as large packet transformations. Give emphasis an entrance, an intentional hold and a release. Interpolate the existing rounded surface's fill, border, text emphasis or opacity; do not introduce another painted wrapper or competing silhouette to animate it. Persistent outcomes settle into a readable state.

Use a shared policy driven by presentation time. Derive each emphasis interval from the operation's prepared read, transfer or decision boundaries. Fit entrance and release to the available interval; merge adjoining intervals on the same target so a continuous operation does not flicker. The current study starts with centrally tunable 180 ms entrance and 220 ms release ceilings, each limited to 35% of a short finite interval. ### Consistent comprehension, varied choreography

**Agreed — 1 October 2026:** keep a dependable reading rhythm while allowing expressive variation in movement. ### Contract for reusable, dynamically adjusting systems

**Agreed:** callers specify semantic intent and constraints; the system computes presentation from the current situation. Reusing a fixed path or accepting caller-supplied positions and timing is not sufficient. **Proposed contract:**

- Inputs: operation and supported outcome, stable source/target identities, content and line geometry, containment/attachment relationships, usable viewport, reserved regions, presentation progress, motion preference, and shared tuning tokens.
- Derived result: target framing, attachment positions, clearance, lens coverage, travel path, phase allocation, and final state. Identical inputs and progress must reproduce the same presentation.
- Shared tuning: readable aperture and magnification limits, reading pace, dwell bounds, travel pace, clearance, easing, and optical quality. Tune these centrally; exact values require visual review.
- Exceptions: a real semantic or teaching difference may select a different shared operation or explicit emphasis. Document the reason and affected scenes. Character-count buckets, literal-value checks, and fixture-specific coordinates are not acceptable substitutes for adaptive behavior.

### Reading lens: content coverage rather than boundary travel

The narrow lens must magnify the actual text beneath it. Travel, acquisition, reading, result, and release are shared phases, not bespoke scripts for each value. Movement, optical focus, and optional subtle shape response follow the same phase progress. Shape response is a material option to review, not the definition of adaptability.

Use actual rendered text bounds, excluding the surrounding field's padding. For one line, let `W` be text width and `A` the usable reading width of the lens expressed in the same coordinates, accounting for magnification and its rim. The approved skinny-scan study distinguishes the optical aperture from a narrower central focus band `F = 0.55 × A`. Its continuous coverage rule is `travel = max(0, W - F)`. The first lens center is `textLeft + min(W, F) / 2`; the last is `textRight - min(W, F) / 2`. The ratio is one shared design setting, not a per-field or character-count branch.

Consequences of the same rule:

- When the text fits the central focus band, both centers coincide at its center. Acquisition and result dwell occur over the value; there is no fabricated sweep from its left margin to its right margin.
- When it exceeds the focus band, the lens moves between positions that bring the first and last portions through that band. A value can fit the wider optical aperture and still receive meaningful travel; this is the approved treatment for the two-digit TTL fixture. It does not dwell outside the text. Reading travel should feel steady; approach/departure easing must not move the reading emphasis into empty margins.
- When text wraps, measured line segments feed the same coverage calculation in semantic reading order. Repositioning between lines is distinct from reading them. A value that should remain unbroken uses an appropriate readable detail view.

Derive reading duration from coverage, content, and shared pace/dwell policies. Keep the result visible while attention is still on the value. Clamp decorative travel and provide pause/inspection access; do not meet a duration ceiling by making essential text unreadable. A missing or unknown value remains explicitly unavailable instead of generating an invented read or successful result.

The rejected scanner lingered at the edges of single-character values while moving past the characters themselves. `4`, multi-character values, long addresses, and wrapped text must work with the same policy and no example-specific motion branches. The policy selects how to present a read; the model or explicitly labeled explanation supplies what to read and whether it passes a check.
