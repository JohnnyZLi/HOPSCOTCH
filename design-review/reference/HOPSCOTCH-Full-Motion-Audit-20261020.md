## Audit coverage and evidence policy

The added `full-motion-audit` compatibility matrix records every source event at **1×** through the end of Journey, TCP, DNS, TLS, packet anatomy, packet operations, provider operations, failure routing, and HTTP comparison, at desktop Light and phone Dark. Reports retain the complete planned phases, content attention budgets, wall-clock samples, source identities, visible reader coordinates and timestamped JPEG screencasts. Shared Builder/Evidence control recordings include interrupted disclosures. These checks join the required compatibility aggregate; existing performance limits remain unchanged.

The matrix has been added but has **not run in CI on this branch**. Local command-line Chrome fails during startup because its required socket operation is denied, before it loads the application. That is not an application test result.

Actual visual review used a separate cloud browser with the production build in paired 1280 × 900 desktop and 390 × 844 phone viewports. At normal speed, review covered all nine families through their final events: Journey, TCP, DNS miss, TLS, packet anatomy, packet operations, provider operations, failure routing, and HTTP comparison. Repairs were iterated between runs; this is not one immutable recording of the final build across the whole matrix. The changed packet-operation viewport, final Journey outcome, coordinated failure/HTTP layouts, Builder panes and Evidence restoration were revisited after their respective repairs.

All six Builder panes were selected and reselected, and a disclosure was reversed in flight. Evidence review imported four synthetic frames, selected frame #4 / IPv4, left the workspace and returned, retaining the original bytes and captured timestamp. The final route handoff was checked across Builder, TCP, Measured and Journey on both viewports; returning to Journey retained its selected DNS-cache-miss event. Repeated screenshot observations showed a composition throughout those client transitions. The added automated check samples every painted frame and still awaits CI execution.

The browser can throttle idle frame delivery near 1 Hz, and screenshots can return the preceding compositor frame immediately after an action. Follow-up images and visible DOM state were used to distinguish these effects. Wall time between tool calls is not a renderer performance benchmark. The observed browser used the fallback material path; hardware GPU performance is not certified by this review.

Local source/production-runtime regressions, bounded composition and source semantics checks, TypeScript checks, the application contract suite and production build pass. These checks protect exact source events/bytes, clock behavior, measured glyph sweeps, rendering bounds, saved selections and cleanup; they do not replace the visual observations above.
